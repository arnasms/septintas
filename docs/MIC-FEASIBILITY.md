# iPhone → Mac microphone: feasibility

Research date: 2026-11-03. Report only; no driver, settings, phone, or runtime changes.

## Decision

**Conditional GO for a Mac-only virtual-input spike before phone implementation.** USB bandwidth is ample; exposing a reliable microphone to arbitrary Mac apps, installing it, and maintaining its clock are the risks. Use a user-space **AudioServerPlugIn HAL driver**, not a kernel extension or AudioDriverKit. Apple explicitly recommends AudioServerPlugIn for virtual devices and says AudioDriverKit supports physical audio devices; its WWDC explanation says virtual-only DriverKit entitlement requests will not be granted. [Apple driver guidance](https://developer.apple.com/documentation/audiodriverkit/creating-an-audio-device-driver), [WWDC21](https://developer.apple.com/videos/play/wwdc2021/10190/).

Suggested architecture: phone capture → timestamped PCM over USB → Mac receiver/resampler → bounded ring buffer → minimal HAL input driver → conferencing/recording app. Keep transport, conversion, UI, allocation and blocking IPC outside the driver's real-time callbacks. The plug-in must return silence when its producer disappears. Treat this architecture as a proposal, not a tested implementation.

## Repository fit

- `Mac/UsbMux.swift` already tunnels a stream through `/var/run/usbmuxd` to phone port 27077 and filters USB attachments. `Phone/PhoneServer.swift` binds loopback and accepts the tunnel. This is the existing transport, **not USB Audio Class**: no evidence here that iOS can enumerate this app as a hardware USB microphone. usbmuxd is a compatibility dependency, not a documented public Apple app transport guarantee.
- `Shared/Wire.swift` / `WireConnection.swift`: v1, `[type:u8][length:u32 big-endian][payload]`, maximum 16 MiB; full-duplex framed socket. No audio message, format negotiation or audio clock exists. Unknown message types are consumed then ignored; Mac currently ignores `hello`, so version constants alone do not negotiate capabilities.
- One serial send queue per direction means camera frames can block following audio; the four-message droppable limit counts messages, not bytes or age. Non-droppable traffic can accumulate. Adding PCM to this queue unchanged risks latency spikes. Prototype bounded audio scheduling; if camera coexistence fails, use a separately negotiated audio usbmux connection/port with its own queues. Separate streams avoid application head-of-line blocking, but still share the USB link.
- Add independent mic enable/status/capabilities messages rather than mode-bound `modeData`: dashboard/second-display and camera should remain usable concurrently. Audio packets need sequence, capture sample position/time, actual format, frame count and discontinuity/session epoch; specify byte order and validate lengths. Negotiate support before sending to old peers.
- `Phone/CameraStreamer.swift` captures video only. Add coordinated AVAudioSession ownership and AVAudioEngine input capture or AVCaptureAudioDataOutput; avoid competing camera/audio session reconfiguration. Apple supports audio and video inputs/outputs in a capture session. [Capture session](https://developer.apple.com/documentation/avfoundation/setting-up-a-capture-session).
- `Mac/VirtualCamera.swift` feeds an already installed OBS camera through CoreMediaIO; that is not a Core Audio microphone endpoint. There is no audio driver target. `project.yml` targets iOS 15/macOS 14; phone plist lacks microphone purpose text. Phone currently stops its server/connection on resign-active (`RootViewController.swift`): foreground-only mic is the honest first scope; lock/background needs separate lifecycle work and device testing.

## Driver approaches and alternatives

| Approach | Practical assessment |
| --- | --- |
| Apple NullAudio-based HAL plug-in | Preferred ownership path. Apple's minimal C sample publishes float PCM I/O at 44.1/48 kHz. Replace synthetic input with a strictly bounded producer bridge; implement stable UID, sample/host timestamps, lifecycle and property notifications. Sample is scaffolding, not a ready IPC microphone. Its downloaded `LICENSE.txt` permits modification/distribution with copyright and permission notice retained. [Sample and download](https://developer.apple.com/documentation/coreaudio/creating-an-audio-server-driver-plug-in) |
| libASPL | Optional C++17 HAL boilerplate layer, MIT licensed; compare dependency maintenance and real-time behavior against the small Apple baseline before adopting. Pin/review a revision. [Project](https://github.com/gavv/libASPL), [license](https://github.com/gavv/libASPL/blob/main/LICENSE) |
| Independently installed BlackHole | Fast integration experiment: Mac writes PCM to its output endpoint; client selects matching BlackHole input. Adds dependency/device-selection friction and lacks a dedicated i7 identity. Do not bundle or fork casually: source is GPLv3; maintainer requests a license for non-GPL integration, and current license separately reserves rights in official binaries/installers. Resolve intended integration/redistribution terms first; independently routing to an installed device is distinct from copying its code. [README](https://github.com/ExistentialAudio/BlackHole), [license](https://github.com/ExistentialAudio/BlackHole/blob/master/LICENSE) |
| Continuity Camera microphone | Best driver-free option on supported phones: microphone can be chosen separately, wired or wireless. Requires iPhone XR or later, iOS 16+, macOS 13+, account/2FA and other Apple prerequisites. Thus unavailable on an actual iPhone 7; actual target hardware was not verified. Lock/mount requirements also conflict with this app's active dashboard use. [Apple requirements](https://support.apple.com/en-us/102546) |
| App-only receiver / recording | Useful transport milestone without a system driver; does not satisfy arbitrary apps' microphone pickers. Aggregate devices combine existing endpoints, not arbitrary socket PCM. Core Audio taps capture outgoing process audio; they do not replace publishing this input device. [Aggregate devices](https://support.apple.com/en-us/102171), [taps](https://developer.apple.com/documentation/coreaudio/capturing-system-audio-with-core-audio-taps) |

## Installation, distribution and permissions

Apple's HAL sample installs a `.driver` in `/Library/Audio/Plug-Ins/HAL` and calls for reboot. Budget administrator-authorized install/update/uninstall and possible reboot/audio interruption; do not promise app-only installation or silently restart coreaudiod. A user-space HAL plug-in does not require a kext or reduced security/SIP changes. AudioDriverKit's app activation/entitlement workflow is a different model. [HAL installation](https://developer.apple.com/documentation/coreaudio/creating-an-audio-server-driver-plug-in).

For distribution outside the App Store, plan Developer ID Application signing of executable bundles, Developer ID Installer signing of PKG, notarization and stapling; validate clean install, upgrade, removal and Gatekeeper on supported macOS/architectures. Existing local self-signed `scripts/build-mac.sh` and disabled hardened runtime are not a distributable signing solution. Budget Apple Developer Program access and review hardened-runtime requirements for each component. Do not assume Mac App Store eligibility for a system-wide HAL installer. [Developer ID](https://developer.apple.com/developer-id/), [notarization/signature requirements](https://developer.apple.com/documentation/security/resolving-common-notarization-issues).

On iPhone, add `NSMicrophoneUsageDescription`, request recording permission at explicit mic activation, and handle denial/revocation, interruptions and route changes. TrollStore delivery does not remove the need to design/test permission behavior. [Apple recording permission](https://developer.apple.com/library/archive/documentation/Audio/Conceptual/AudioSessionProgrammingGuide/RequestingPermission/RequestingPermission.html). Mac consuming apps must receive microphone access through normal TCC; a virtual device is not a permission bypass. If i7 itself captures input for monitoring/testing, include the appropriate purpose string and capture entitlements for its distribution configuration; verify current macOS prompts in the spike. [Capture authorization API](https://developer.apple.com/documentation/avfoundation/avcapturedevice/requestaccess(for:completionhandler:)). Avoid system-audio capture permissions by not adding unrelated taps.

## Latency and clock design

Start mono 48 kHz PCM16: **96 kB/s**, 960 bytes per 10 ms packet (plus headers); float32 doubles bandwidth. No codec is needed initially. Request 5–10 ms phone I/O, but inspect actual rate/buffer after activation: preferences are hints. [Apple QA1631](https://developer.apple.com/library/archive/qa/qa1631/_index.html).

Planning budget, **not measured**: phone capture/packetization 5–20 ms + USB/scheduling 1–10 ms + jitter reserve 10–30 ms + HAL/client buffering 5–20 ms ≈ 21–80 ms before application processing. Measure under simultaneous camera and second-display traffic; USB alone guarantees no latency figure. Prefer a bounded 20–30 ms starting jitter target, silence on underrun and bounded discard/crossfade on discontinuity rather than replaying stale speech. Report actual HAL latency/safety offset consistently with buffering.

Phone ADC and Mac host clock are independent. At an illustrative 100 ppm mismatch, 48 kHz drifts 4.8 frames/s (6 ms/minute); a larger queue only postpones failure. Use Mac host time for HAL sample timestamps; estimate phone rate from sample counters/timestamps and slowly adapt an asynchronous resampler using buffer occupancy. Reset on reconnect, interruption or format change. Host clocks have different epochs: map them with timestamp exchanges if absolute A/V alignment is required. Apple's aggregate-device guidance confirms even nominally equal sample rates can drift; its drift correction does not automatically fix a custom socket producer. [Apple synchronization](https://support.apple.com/guide/audio-midi-setup/set-aggregate-device-settings-ams094c7edb4/mac).

## Stages and gates

1. **Mac-only risk spike, first:** synthetic tone → proposed producer bridge → HAL mic; no phone dependency. On an explicitly approved test machine later, prove enumeration/selection in Audio MIDI Setup, QuickTime, browser WebRTC and a conferencing app; two simultaneous readers; silence after producer crash; clean install/update/uninstall. GO only if no security reduction is needed and signing/licensing/distribution route is acceptable. Do not invest in phone capture before this gate.
2. **Transport/capture prototype:** negotiate mic support; explicit enable/disable and permission errors; foreground PCM to a Mac recording sink, then HAL. Verify old peers fail gracefully, bounded queues, unplug/reconnect and rate changes. Use `I7_DIRECT_PORT` for deterministic fake-phone transport tests before hardware.
3. **Timing/coexistence:** measure acoustic/electrical end-to-end delay, queue occupancy and underruns over ≥60 minutes with camera + second display/dashboard; exercise interruptions, denial, sleep/wake and client restart. Proposed gate: p95 mic latency ≤80 ms, no sustained queue growth, no audible drift/dropouts in steady operation, silence within 100 ms of detected loss and recovery ≤3 s after transport returns. These are acceptance targets, not Apple guarantees; client processing may require revising the end-to-end budget.
4. **Delivery hardening:** validate signed/notarized artifacts on macOS 14 and the newest supported release, arm64 and x86_64 if shipping both; retain third-party notices and document manual installation/removal. Keep phone delivery through the existing manual TrollStore IPA route.

**NO-GO / rescope:** unacceptable admin install/reboot, unresolved licensing/signing, unreliable HAL/client compatibility, or failure to bound drift/latency under video load. Fall back to an independently installed loopback device or app-only recording; Continuity mic only where hardware/workflow permits. All device behavior, permission prompts, driver loading, latency and compatibility remain unverified: this change is research only, with no build or phone test required.
